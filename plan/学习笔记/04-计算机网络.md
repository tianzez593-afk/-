> 对应图片里的「网络」。
> 目标：能讲清「输入网址到页面出现」发生了什么，能回答常见面试题。

---

## 先记住这几件事

1. 一次网页访问，大致经过：DNS → TCP → HTTP → 服务器 → 响应 → 浏览器渲染。
2. HTTP 是「请求-响应」模型，无状态。
3. TCP 可靠、面向连接；UDP 快、不保证可靠。
4. HTTPS = HTTP + TLS，解决明文传输问题。
5. 状态码分五类：1xx 信息、2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务端错误。

## 一、输入网址到页面出现

```text
1. 浏览器解析 URL
2. DNS 解析：域名 → IP 地址
3. 建立 TCP 连接（三次握手）
4. （HTTPS）TLS 握手
5. 发送 HTTP 请求
6. 服务器处理，返回 HTTP 响应
7. 浏览器解析 HTML/CSS/JS，渲染页面
8. 关闭 TCP 连接（四次挥手）
```

### 每一步在做什么

| 步骤 | 作用 |
| --- | --- |
| DNS | 把 `www.example.com` 翻译成 `93.184.216.34` |
| TCP 三次握手 | 确认双方都能收发 |
| TLS 握手 | 协商加密方式，验证证书 |
| HTTP 请求 | 告诉服务器要什么 |
| HTTP 响应 | 服务器返回状态码、头、正文 |
| 渲染 | 浏览器把 HTML 变成页面 |

## 二、HTTP

### 请求方法

| 方法 | 用途 | 幂等 |
| --- | --- | --- |
| GET | 获取资源 | 是 |
| POST | 新建资源 / 提交数据 | 否 |
| PUT | 整体更新 | 是 |
| PATCH | 部分更新 | 否 |
| DELETE | 删除 | 是 |

> 幂等 = 执行多次，结果一样。

### 常见状态码

| 状态码 | 含义 |
| --- | --- |
| 200 | 成功 |
| 201 | 已创建 |
| 204 | 成功但无内容 |
| 301 | 永久重定向 |
| 302 | 临时重定向 |
| 304 | 缓存未修改 |
| 400 | 请求参数错误 |
| 401 | 未认证 |
| 403 | 已认证但无权限 |
| 404 | 资源不存在 |
| 405 | 方法不允许 |
| 500 | 服务器内部错误 |
| 502 | 网关错误 |
| 503 | 服务不可用 |

### 常见请求头

```text
Host: example.com
User-Agent: ...
Accept: text/html
Content-Type: application/json
Authorization: Bearer <token>
Cookie: sessionid=...
```

### 常见响应头

```text
Content-Type: application/json
Content-Length: 1234
Set-Cookie: sessionid=...
Cache-Control: max-age=3600
```

## 三、TCP 与 UDP

| 特性 | TCP | UDP |
| --- | --- | --- |
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠，丢包重传 | 不保证 |
| 顺序 | 保证顺序 | 不保证 |
| 速度 | 较慢 | 较快 |
| 场景 | 网页、文件、数据库 | 视频、游戏、DNS |

### 三次握手

```text
客户端 → 服务端：SYN
服务端 → 客户端：SYN + ACK
客户端 → 服务端：ACK
```

目的：确认双方都能发送和接收。

### 四次挥手

```text
客户端 → 服务端：FIN
服务端 → 客户端：ACK
服务端 → 客户端：FIN
客户端 → 服务端：ACK
```

> 面试常问：为什么是三次握手、四次挥手？
> 答：握手要确认双向通道；挥手因为 TCP 是全双工，两个方向要分别关闭。

## 四、DNS

```text
浏览器缓存 → 系统缓存 → hosts 文件 → 本地 DNS 服务器
→ 根域名服务器 → 顶级域名服务器 → 权威域名服务器
```

常见记录：

| 类型 | 作用 |
| --- | --- |
| A | 域名 → IPv4 |
| AAAA | 域名 → IPv6 |
| CNAME | 别名 |
| MX | 邮件服务器 |

## 五、HTTPS

### HTTPS 做了什么

1. 加密：防止中间人看到内容
2. 身份验证：证书确认服务器身份
3. 完整性：防止内容被篡改

### TLS 握手（简化）

```text
客户端：支持的加密套件 + 随机数
服务端：选中的套件 + 随机数 + 证书
客户端：验证证书，生成预主密钥，用公钥加密
双方：生成会话密钥
开始加密通信
```

> 面试不需要背完整握手，能说清「非对称加密协商出对称密钥」即可。

## 六、Cookie / Session / Token

| 方式 | 存在哪 | 特点 |
| --- | --- | --- |
| Cookie | 浏览器 | 每次请求自动带上 |
| Session | 服务器 | 服务器存状态，靠 Cookie 里的 sessionid 关联 |
| Token（JWT） | 客户端 | 服务器不存状态，靠签名验证 |

## 八、动手实验

### 实验 1：浏览器开发者工具

1. 打开任意网站，按 F12
2. 切到 Network
3. 刷新页面
4. 点第一个请求，记录：
   - URL
   - 方法
   - 状态码
   - 请求头
   - 响应头

### 实验 2：curl

```cmd
curl -I https://www.example.com
curl -X GET https://httpbin.org/get
curl -X POST https://httpbin.org/post -H "Content-Type: application/json" -d "{\"name\":\"test\"}"
```

### 实验 3：DNS

```cmd
nslookup www.example.com
ping www.example.com
```
