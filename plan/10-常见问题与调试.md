> 对应图片里的「bug - figure out - error - rollback」。
> 这一份不是让你背，是卡住的时候来查。

## 一、卡住时的 30 分钟规则

1. **先自己想 20 分钟**：看报错、看文档、试一个小改动。
2. **第 20–30 分钟**：把问题写成 3 行：
   ```text
   我想做什么：
   报错是什么：
   我试过什么：
   ```
3. **30 分钟后**：再问人 / 问 AI。
4. **解决后**：用 `07-每日每周模板.md` 的 Bug 模板记录下来。

> 不记录的问题，等于没解决。下次还会卡。

## 二、怎么读 Python 报错

例子：

```text
Traceback (most recent call last):
  File "word_count.py", line 8, in <module>
    text = open("sample.txt").read()
FileNotFoundError: [Errno 2] No such file or directory: 'sample.txt'
```

读法：

1. **看最后一行**：`FileNotFoundError` 是错误类型，后面是具体信息。
2. **往上找自己的文件**：`word_count.py, line 8`。
3. **看那一行**：`open("sample.txt")`。
4. **推断**：文件不存在，或者路径不对。

### 常见 Python 错误

| 报错 | 常见原因 | 怎么查 |
| --- | --- | --- |
| `SyntaxError` | 少了冒号、括号、引号 | 看报错指的那一行和上一行 |
| `IndentationError` | 缩进不一致 | 统一用 4 个空格 |
| `NameError` | 变量名拼错 / 没定义 | 检查拼写和作用域 |
| `TypeError` | 类型不对，比如 `str + int` | 打印 `type(x)` |
| `ValueError` | 值不对，比如 `int("abc")` | 检查输入 |
| `KeyError` | 字典里没有这个键 | 用 `.get()` 或先判断 |
| `IndexError` | 列表越界 | 打印长度 |
| `FileNotFoundError` | 路径不对 | 打印当前目录和绝对路径 |
| `ModuleNotFoundError` | 没安装 / 虚拟环境不对 | `pip install`，确认激活了 venv |

## 三、怎么问一个好问题

不要问：

```text
我的代码报错了，怎么办？
```

要问：

```text
我想做什么：读取 sample.txt 并统计词频
报错：
FileNotFoundError: ... 'sample.txt'
我试过：
1. 确认文件在 day02 文件夹里
2. 用绝对路径也报错
3. 打印了 os.getcwd()，发现当前目录是 E:\learning-log
我的猜测：路径是相对于运行命令的目录，不是脚本所在目录
```

这样别人（或 AI）能直接定位。

## 四、Git 常见错误

### 1. `not a git repository`

当前目录不是 Git 仓库。

```cmd
git init
```

或者 cd 到正确的项目目录。

### 2. `push rejected` / `non-fast-forward`

远程有你本地没有的提交。

```cmd
git pull --rebase
git push
```

如果冲突，先解决冲突再提交。

### 3. 合并冲突（CONFLICT）

打开冲突文件，会看到：

```text
<<<<<<< HEAD
你的代码
=======
别人的代码
>>>>>>> branch-name
```

手动保留想要的内容，删掉 `<<<<<<<`、`=======`、`>>>>>>>`，然后：

```cmd
git add .
git commit -m "resolve conflict"
```

### 4. `detached HEAD`

你切到了一个提交，而不是分支。

```cmd
git switch main
```

### 5. `Authentication failed`

GitHub 不再接受密码。用：

- VS Code 的源代码管理面板，点推送，浏览器登录
- 或 GitHub Desktop
- 或 Personal Access Token

### 6. 想撤销但还没提交

```cmd
git restore 文件名
```

### 7. 想撤销已经提交的一次

```cmd
git revert 提交号
```

> `revert` 是安全的，会生成一个新提交来抵消旧提交。
> `reset --hard` 会丢东西，初学阶段不要用。

### 8. 提交了不该提交的文件（比如 `.venv`）

1. 先在 `.gitignore` 里加：
   ```text
   .venv/
   __pycache__/
   db.sqlite3
   ```
2. 如果已经提交：
   ```cmd
   git rm -r --cached .venv
   git commit -m "stop tracking .venv"
   ```

## 五、Python 环境常见问题

### `pip` 不是内部或外部命令

用：

```cmd
python -m pip install 包名
```

### 安装了包，但运行时说找不到

大概率是虚拟环境没激活，或者装到了另一个 Python。

```cmd
where python
python -c "import sys; print(sys.executable)"
```

确认当前 Python 是你要用的那个。

### 虚拟环境怎么建、怎么激活

```cmd
python -m venv .venv
.venv\Scripts\activate.bat
```

激活后命令行前面会出现 `(.venv)`。

### 退出虚拟环境

```cmd
deactivate
```

## 六、调试方法：复现 → 隔离 → 假设 → 验证

### 1. 复现

先能稳定地让 bug 出现。记录：

- 输入是什么
- 点了什么
- 环境是什么

### 2. 隔离

把问题缩小：

- 注释掉一半代码，看还报不报错
- 把大函数拆成小函数，逐个测试
- 用一个最小例子复现

### 3. 假设

猜一个原因，例如：

- 「是不是文件路径不对？」
- 「是不是变量是 `None`？」
- 「是不是接口返回了 500？」

### 4. 验证

用 `print`、断点、日志、`curl` 去验证，不要靠猜。

### 5. 记录

解决后写 Bug 记录：现象、原因、解决、下次怎么避免。

## 七、怎么用 AI / Cursor 才不废掉自己

### 可以让 AI 做

- 解释报错
- 解释一段代码
- 给思路，不给完整答案
- 帮你写测试用例
- 帮你检查边界情况

### 不要让 AI 做

- 直接生成整个项目，你只复制粘贴
- 生成你看不懂的代码
- 替你决定架构

### 一条硬规则

> **你保留的每一行 AI 代码，你都必须能逐行解释。**
> 解释不了，就删掉自己重写。

### 让 AI 解释代码的提问模板

```text
请逐行解释这段代码，重点说明：
1. 每个变量是什么类型
2. 函数之间的调用关系
3. 哪里可能出错
4. 如果我要改 XXX，应该改哪里
```

## 八、学习卡住了怎么办

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 看视频都懂，一写就废 | 输入太多，动手太少 | 关掉视频，从最小例子写 |
| 题目看了题解也不会 | 基础不牢 | 回到对应知识点，做 5 道更简单的 |
| 学了两周感觉没进步 | 没有产出 | 做一个能运行的小东西 |
| 同时学太多，哪科都卡 | 注意力分散 | 一周只主攻一个主题 |
| 一遇报错就想放弃 | 没有调试方法 | 用「复现→隔离→假设→验证」 |
| 总觉得别人更强 | 比较对象错了 | 只和两周前的自己比 |

## 九、每天收工前的 3 个问题

1. 今天写了多少行代码？
2. 今天有没有一个「以前不懂、现在懂了」的点？
3. 明天第一件事做什么？

回答不出来，说明今天只是「看起来很努力」。
